---
name: ai-edit-ephemeral-outputs
description: Avoid persisting temporary AI agent outputs during interactive editing.
---

## The Problem
When an AI agent performs interactive editing (e.g., suggesting code changes, generating content) that might be rejected by the user, writing intermediate or temporary outputs directly to the user's file system can lead to orphaned files, directory clutter, or unexpected state.

## The Lesson
For interactive AI editing flows, treat all agent-generated changes as *ephemeral and in-memory* until the user explicitly accepts or commits them. Only persist changes to disk or external systems *after* user confirmation.

## Why it Matters
*   **Cleanliness:** Prevents orphaned files and avoids cluttering the user's workspace with discarded temporary artifacts.
*   **Data Integrity:** Ensures that only user-approved changes are committed to persistent storage, preventing unintended modifications or corrupted states.
*   **User Experience:** Provides a predictable and safe editing environment where users feel in control, knowing that their file system won't be modified without their explicit consent.

## Example (from this PR)
In AI-powered workflow editing, sub-agent definitions generated by the AI should remain inline within the workflow's in-memory representation. They are only materialized as separate `.md` files on disk (e.g., in `.claude/agents/`) when the workflow is explicitly *exported* or *run*, not during an `apply_workflow` operation for an AI-edit diff that might be rejected. This ensures that rejecting an AI-edit diff does not leave behind mis-named or orphaned sub-agent files.

## Applicability
This principle applies to any AI agent that proposes changes to a user's workspace, code, or data where the user has the option to review and reject the proposed changes.
