Purpose: Integrates new AI models or providers by establishing a single source of truth for their enumerated values across the system.

## Workflow

1.  **Establish Single Source of Truth (SSoT)**:
    *   In the designated core schema directory (e.g., `packages/core/src/schema/`), define the new enumerated value within the primary constant array that holds these values (e.g., `SUB_AGENT_MODEL_VALUES`).
    *   Derive the corresponding TypeScript `type` from this array (e.g., `SubAgentModel`).
    *   If applicable, update any related constants that depend on these values (e.g., `CC_ONLY_MODELS` for provider-specific exclusions).

2.  **Update Core Schema and Validation**:
    *   Add the new value to the central workflow schema definition (e.g., `packages/core/resources/workflow-schema.json`) within the relevant `enum` definition. Note that associated `.toon` files are typically auto-generated by the build.
    *   Update the core validation utility (e.g., `packages/core/src/utils/validate-workflow.ts`) to correctly validate the new value against the SSoT constant.

3.  **Integrate with Core Services**:
    *   Modify core services that consume these values (e.g., agent skill export, workflow prompt generation services within `packages/core/src/services/`) to properly reference the new SSoT constants and derived types.

4.  **Propagate to Shared Types**:
    *   Ensure any shared types that consume these values (e.g., `packages/core/src/types/workflow-definition.ts`, `packages/core/src/constants/built-in-sub-agents.ts`) reference the new derived type from the SSoT.

5.  **Update UI Components**:
    *   In the webview constants directory (e.g., `packages/vscode/src/webview/src/constants/`), create or update a constant file (e.g., `model-options.ts`) that imports the SSoT array from core and maps it to UI-friendly options (e.g., `{ value, label }`).
    *   Modify all relevant UI components (e.g., property overlays, form dialogs, slash command dropdowns) to use these new webview constants, replacing any hardcoded arrays or manual type assertions.

## Checklist

*   [ ] `tsc --noEmit` passes for all packages (`core`, `mcp`, `cli`, `vscode`).
*   [ ] `pnpm build` completes successfully.
*   [ ] Manual E2E testing confirms the new value appears correctly in all UIs (dropdowns, forms, etc.).
*   [ ] Manual E2E testing verifies the new value is handled as expected in export, validation, and execution flows (e.g., if it's a model, ensure it's correctly omitted for non-compatible providers).
